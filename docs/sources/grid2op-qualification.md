# Grid2Op held-source qualification boundary

SPDX-License-Identifier: CC-BY-4.0

This assessment gives information about held power-grid inputs and their native development check.
It separates an exposed chronic from a prospective independent episode roster.
Use it to identify the required source files and present integration stop.

The retained Grid2Op independent-recurrence adapter is a native numerical power-grid route.
The [target-owned development quick start](../../experiments/grid-response-inputs/guide.md) now
loads an operator-selected held source through the one CLI. Its shipped
selection intentionally names an absent researcher chronic and refuses before
contact until a real input is provided. It does not qualify a prospective
roster or compile a campaign.
Its source binding requires these inputs:

- Grid2Op 1.12.5 and LightSim2Grid 0.13.1 wheel bytes.
- An offline `l2rpn_case14_sandbox`-format grid directory.
- `grid.json` and `config.py`.
- Exact chronic directories with load and production series, start time and timestep.
 The source builder records package, grid,
rule, observation-operator and exogenous chronic identities. One complete
chronic is an independent unit. Reset/replay action branches and their
receiver horizons are nested views. [Grid2Op's official environment
documentation](https://grid2op.readthedocs.io/en/stable/available_envs.html)
describes the public sandbox family. Source data and any dataset license need
to be checked at acquisition. This repository does not bundle the data.

An excluded historical qualification chronic was read in place from the
read-only source mount under the pinned optional stack. The target adapter
built its exact held-source binding and executed hold and line-000 disconnect
branches at receiver steps 1 and 3. Both branches began from the same reset
state, and the complete episode retained **one** chronic unit. The disconnect
was requested, accepted, applied and realized at both horizons, with one
disconnected line and higher maximum thermal loading than hold.

Hold kept
zero disconnected lines. This is a bounded native semantic check of the
adapter. It does not reissue the historical chronic as prospective evidence. A request with a mismatched source identity was refused before the execution
port received any branch call.

The first historical source closeout stopped because its native source was absent.
A later historical source qualification preceded an exposed 18-unit evaluation.
That evaluation found a decisive counterexample to its frozen recurrence forecast. Those outcome-visible units and the old correction cannot become a
new target candidate or independent confirmation. A researcher needs a
newly frozen, disjoint chronic roster and trusted offline storage.

The target
has a checked-in development selector and native one-CLI check, but no selected
campaign provider or strict candidate/no-effect production path. Fresh
prospective custody remains unverified. These integrations are deferred for
the first release. The checked development route retains the limits above.
