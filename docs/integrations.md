## One application handoff and the existing lifecycle

Authoring produces a closed, guarded external directory containing the actual candidate, plan, projection and inputs. `campaign integration-proof --authoring-dir DIR` reconstructs the full selected graph/provider/resources without executing scientific tasks. Select the same directory with the global `--authoring-dir DIR` for subsequent existing application operations. There is no dynamic module name, implicit latest directory or parallel scheduler.

Use a selected clean checkout and explicit `--project-root`/`--operator-profile`. The checkout's existing [readiness](../src/empirical_lawhood/api/execution.py), issue, scientific approval, execution-package and elapsed-budget contracts still apply; [the CLI reference](cli.md) lists exact input options for each operation. Authoring/proof creates no issue, execution, reveal or owner authority. Finite-response runtime binding explicitly attaches actual current grants after issue; absence refuses before execution.

`campaign status` reports execution and receipt state. Family result commands provide scientific readouts and next-stage operands from selected exact receipts. Current results must match their stored issued task and complete declared output census. Protected reads replay current issue/execution/reveal authority before reading outcome bytes and verify the complete sibling publication. Original or exposed development grants cannot authorize a new study.

`campaign resume` uses the same handoff, store and immutable plan with retained receipts. It preserves existing retry/resource/cumulative-time constraints. A valid later authorized receipt is addressed by its exact identity, never an assumed first attempt. Recovered work cannot repeat completed acquisition solely to obtain a preferred outcome.

Native development source exports and saved-array analyses retain their own bounded operation attempts. Incomplete native exports preserve selected source/allocation and completed cells; the absent completion manifest means they cannot be consumed as complete banks. Use the documented exact receipt recovery where supported; an unreceipted partial publication requires a fresh explicit destination. Native software conformance exercises bounded source/view cells and grants no scientific qualification.

The maintained architecture and environment guides describe the reused owners. Geometry/selected-event development operations and history/tangent acquisition use the existing guarded artifact/receipt owners with explicit non-promotable ceilings; they create no issued campaign authority. Saved analysis readers authenticate original input/output bytes and lineage without repeating acquisition or fitting. Geometry selection failure is a readable negative terminal; missing histories retain the full requested census and remain unevaluable.

The complete supported portable suite runs once on the frozen staged candidate before its integration commit. The separate artifact gate accepts authenticated precommit evidence only when that candidate exactly matches the final clean commit, preserving its original test attribution. Build, package comparison and installed smoke add current artifact evidence without another full-suite call; full scientific campaigns and release publication remain separate operations.
