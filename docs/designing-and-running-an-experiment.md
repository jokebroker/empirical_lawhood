# Design and run an experiment

This guide gives instructions for scientific design, candidate construction and the separately authorized experiment lifecycle.
It applies to the checked family boundaries in the route register.
Use it to select a route and identify its first missing input.

Select a [retained route](substrate-route-register.md).
Its quick start must identify the actual native or post hoc input, install group, scientific check and supported boundary. A static adapter or capability registration is not an
executable experiment. The [CLI reference](cli.md) lists every installed
command and its typed inputs.

## Start with a development configure/run/read loop

Choose a [workflow](../experiments/README.md), then inspect its static requirements:

```sh
uv run --no-sync empirical-lawhood workflow show rc-ladder-response --format json
```

For the numerical RC diagnostic, copy `experiments/rc-ladder-response/model.json` outside the checkout.
Use [configuration validation and preparation](configuration.md) after an allowed edit.
Keep the original and prepared digests. Select the guide's environment and run the prepared input
with an explicit new development output directory. Read the retained report and its scientific ceiling.
The [RC guide](../experiments/rc-ladder-response/guide.md#edit-a-development-model) gives the complete commands.

Formatting a copy does not change a typed model. Changing a resistance does change the model.
Neither operation supplies a new physical board or fresh qualification.
A development result can motivate the next question. Its existing exposure and outcome access remain declared.
[Results and failures](results-and-failures.md) explains successful, negative, incomplete and refused attempts.
The issued lifecycle below is a separate procedure, with genuine inputs and authority.


## Follow one scientific composition

A workflow selection chooses an existing input and operation boundary.
A scientific composition binds a producer's exact evidence to a later consumer.
An application composition binds the providers, codecs, storage and authority ports for that design.
A workflow label or registered provider does not create a scientific parent.

Consider the [current finite-response family](../experiments/finite-response-law/guide.md).
The question is whether a fixed nominated predictor supports forecast-mediated use on a separate prospective cohort.
The native source supplies prepared states and responses.
The calibration and qualification methods assess the fixed predictor.
The evaluation controller freezes forecasts before request and future-outcome reveal.
The nomination retains its original development evidence.

## Freeze the scientific design

Before outcome contact, declare the source and license/access basis, native
parameters and units, coordinate frame, denominator and preparation history. Write the requested action.
Write the native-delivery observation, receiver and horizon.
Write the cutoff, independent-unit rule, nested numerical views, controls and decisive falsifier. Separate development units from new evaluation units. The quick-start configs are development examples.

Exposed unit IDs, seeds or
outcomes cannot become a new unexposed evaluation cohort by changing an
experiment ID. Methods attach to the named consuming native route. A post-hoc method needs its declared typed outcome inputs and authenticated custody.
The consuming contract determines any scientific qualification requirement.

## Author and prove without contact

Use an adapter-owned authoring command only where the selected route guide documents one.
The installed authoring paths cover the reactor prefix, numerical RC ladder, analytic electron gas, synthetic lattice-pairing method and exposed six-matrix response routes.
Native diagnostics, input preflights and deferred integrations keep their stated boundaries. They do not gain an authoring path from this lifecycle.

For an authoring route, supply its strict checked-in input or a new input supported by that family's contract.
The command emits the documented typed study/candidate packet and its declared payloads and decoder proposals.
The normal engine separates the scientific `CampaignSpec`, the compiled `ProtocolRunPlan`, and the lowered `ProtocolExecutionPlan`.
Those records do not prove a task executed.
The [assigned reactor authoring walkthrough](fresh-experiment.md) describes the assignment profile and the proof before native contact.
Its fixed exposed profile is a development example.
The [RC numerical guide](../experiments/rc-ladder-response/guide.md) gives the local model route.

Keep the target Git commit clean and fixed. Create an
`OperatorStorageProfile` with an external guarded mount, distinct artifact
and scratch namespaces and enough free space. The profile identifies storage
but grants no scientific or execution authority. Follow the proof or readiness handoff documented by the selected family guide. Where that guide uses `campaign
check-readiness`, the command takes the exact authoring file, each extension
payload and decoder, expected candidate, source closure, resource envelope
and prospective run ID. It resolves selected providers, runners, native input
identities, output and adjudication locators, resources and authority gates
without native effects. If an adapter or source contract gives a refusal, do not request an issue.

## Issue, execute, recover and reveal

For a genuinely new, unexposed and source-qualified roster, an accountable
operator supplies the required typed proposer attestation and separate
custody/publication authority to `campaign issue` and `campaign issue-extensions`. Scientific approval and execution authority are separate inputs to `campaign
assemble-package`. The issued graph is then compiled and run using
`campaign compile-plan` and `campaign run`. `campaign resume` recovers under the
same issued authority and immutable receipts.

A distinct reveal authorization
permits evaluator access and scientific adjudication. Before you make an evidence claim, examine actual native task receipts and the adjudication record. The [reactor operator walkthrough](reactor-operator.md) gives the complete
storage/trust setup, record constructors and returned-ID handoffs through
recovery. The [CLI reference](cli.md) gives the exact command options.

Neither a preissue proof nor a successful native diagnostic is an
issued run.

External or hardware routes require the operator's allowed source bytes,
calibration and access grant in the family's stated format. Their precontact
checks can validate a source or decoder without asserting instrument contact
or native truth. If the register describes a deferred integration, use only its advertised checked boundary.
A missing candidate, provider, scientific check or authentic input prevents complete experiment execution.
