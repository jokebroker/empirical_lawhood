# Explicit input identities

SPDX-License-Identifier: CC-BY-4.0

This reference gives information about explicit input identities and the supported historical import boundaries.
It prevents source records and authority from changing through namespace substitution.
Use it to construct canonical inputs and identify a required refusal.

The public package is a new software and schema identity. It does not decode an
earlier project's issued record by changing its namespace or claim the earlier
receipt as its own. External input paths, their expected digests, custody and
authority are separate operands. Supplying a digest never grants authority.

The following target contracts replace installation-specific predecessor
defaults while retaining exact comparisons. These are compatibility boundaries,
not a claim that the deferred families have passed native qualification.

| Contract | Public boundary |
|---|---|
| Reactor prefix | Fixed exposed and explicitly assigned prefix records have distinct schemas. Assigned records bind five native seeds and their complete prior census. |
| Reactor response-route ports | `EnvironmentBoundReactorSourceBinding` requires `EmpiricalNativeEnvironment`. The source envelope preserves the exact supplied environment fingerprint. No image is inferred from a directory. |
| Reactor discovery and comparators | Bounded discovery bytes and domain specification are separate inputs. `RegimeReferenceComparators` binds explicit comparator hashes. Required preparation and development parents remain explicit. |
| Six-matrix finite response | The packaged specification binds its exact public plan. Assigned calibration, evaluation and completion records preserve distinct cohorts, explicit numeric seeds and qualified-parent requirements. |
| Six-matrix retained parents | Separate target custody, reveal and analysis publications are required. Refinement/calibration use typed qualified parents. Retained composition uses exact original-root scalar joins. |
| Material methods and controls | `SyntheticMaterialMethodPrerequisites` and `MaterialControlInputPrerequisites` preserve exact source, roster, freeze and conformance digests. Method fixtures do not qualify material controls. |
| Gym–TORAX composition | `GymToraxPredecessorInputs` binds protocol, excluded feasibility, diagnostic records, source roster and response contract. Recovery never changes exposure or predecessor identity. |
| Quantum trajectories | Declared predecessor inputs bind external roots, payload inventory and implementation digest. Bounded replay preserves exact receipt comparisons and negative conditions. |
| Virtual cell | Distinct pipeline and provenance-bound materialization contracts preserve actual source, feature, build and provenance receipts. Authentic inputs and native dependencies remain required. |
| Laser archive | `GlennRetainedComparisonInputs` supplies retained read-set and comparison digests. A diagnostic projection and reproduction receipt remain explicit exploration inputs. |
| Other retained authoring | Prepared refinement needs a qualified prepared evaluation. Static equilibrium needs its authoring manifest. Reference providers require the actual registry and fingerprint. |

All public record revisions start at the selected 1.0.0 baseline.
Distinct scientific roles keep distinct schema identities.
A historical record retains its original schema, bytes and custody.
It cannot become a current record through namespace substitution.

Installed component fingerprints and both generated aggregates refer to target
code and schemas. Public upstream archive, release, source-file and solver pins
remain unchanged where their bytes are unchanged. A source specification digest
and an external receipt digest have different meanings even when both use SHA-256.

See the [reactor](../experiments/reactor-response/guide.md) and [six-matrix](../experiments/prepared-response/guide.md) guides for
the runnable selection and refusal paths, and the [route register](substrate-route-register.md)
for deferred families and their existing evidence ceilings.

## Exposed input construction examples

Every identity and seed in this directory is public, exposed development input.
These files grant no authority, demonstrate no complete historical census, and
must not be used as a fresh qualification roster. Reproduce their bytes with
`uv run --no-sync python scripts/generate_operator_examples.py --check`.

| File | Meaning and fields to inspect |
|---|---|
| [reactor-assigned-exposed.json](../experiments/reactor-response/exposed-inputs/reactor-assigned-exposed.json) | Canonical `AssignedReactorAuthoringProfile`, version `1.0.0`. `value.experiment_id` determines `assignment.assignment_id` and all five unit IDs. `assignment.units` follows `SCENARIOS` order. The same seed supplies both arms and both numerical views of each independent unit. `assignment.prior_census` fingerprints the embedded complete sample census. That census points to the inventory below. The evidence role explicitly prevents an eligibility claim. |
| [exposed-inventory.json](../experiments/reactor-response/exposed-inputs/exposed-inventory.json) | A sample provenance inventory binding the **actual bytes** of the two six-matrix examples by relative locator and SHA-256. `history_complete=false` is deliberate. An inventory digest binds bytes. It cannot establish that omitted history does not exist. |
| [prepared-response-prior-exposure.json](../experiments/reactor-response/exposed-inputs/prepared-response-prior-exposure.json) | Prepared-response/information-response/causal-response exposure import envelope. The four sorted arrays live under `value`. Excluded and previously proposed entries are both retained in the next exclusion set. |
| [finite-response-prior-exposure.json](../experiments/reactor-response/exposed-inputs/finite-response-prior-exposure.json) | Finite-lawhood exposure metadata. Its four arrays are at the document root, not under `value`. This is the retained import format, not a general canonical-record envelope. |

Canonical records have `schema`, `version`, and `value`. Nested records carry
their own envelopes. Use constructors plus `canonical_bytes()` to emit them.
Do not add JSON comments.
Do not replace a hash after you edit scientific fields.
Do not move arrays between these two six-matrix import formats. Duplicate keys, NaN, unsorted
or repeated entries, and conflicting route schemas refuse before compilation.

For the accepted external formats and provenance procedure, read
[six-matrix input formats](response-input-formats.md). The
[reactor operator walkthrough](reactor-operator.md) explains the
assignment, census, authoring and authority handoffs.
