# Information response: fitted-bank authoring and retained diagnostics

SPDX-License-Identifier: CC-BY-4.0

This guide gives instructions for fitted-bank information-response authoring and retained diagnostics.
It preserves measured parent features and whole-root analysis within exposed development.
Use it to compile a development candidate or identify the authenticated analysis inputs.

**Exposed development and post-hoc library diagnostics.** Held fitted-bank authoring compiles a candidate without native execution. The retained reports remain outcome-visible and nonpromotable.

This numerical study compares preservation of information after a measured parent handoff using a frozen fitted bank. Its authoring design has 64 independent stochastic roots, with two numerical views nested under each root. The selected native development check runs only one exposed root.

## Author an exposed development candidate

The local [information-author.json](information-author.json) selects this route. Use absolute paths for the held source, reviewed plan, design packet and complete prior-exposure census. Select the fitted bank whose plan digest matches those exact plan bytes. Choose a new output directory outside the checkout.

```sh
uv sync --locked --python 3.11.14
uv run --no-sync empirical-lawhood --project-root "$PWD" campaign matrix-response-author \
  --config experiments/information-response/information-author.json \
  --source-root "$PREPARED_RESPONSE_HELD_SOURCE_ROOT" \
  --plan "$INFORMATION_RESPONSE_PLAN" \
  --design-packet "$INFORMATION_RESPONSE_DESIGN_PACKET" \
  --prior-exposure "$INFORMATION_RESPONSE_PRIOR_EXPOSURE" \
  --model-bank "$INFORMATION_RESPONSE_MODEL_BANK" \
  --output-dir "$INFORMATION_RESPONSE_NEW_AUTHORING_DIRECTORY"
```

The candidate is `EXPOSED_DEVELOPMENT_NONPROMOTABLE`. The summary reports provider construction and candidate compilation separately. It executes no native task and grants no issue or reveal authority. See [external input formats and shared authoring contracts](../../docs/response-input-formats.md) for exact formats, byte limits, exclusions, expected emitted records and refusal codes.

Follow the [shared matrix export and recovery policy](../../docs/response-input-formats.md#export-and-recover-a-matrix-authoring-bundle)
for the nonexistent external output path, completed products and partial-export
recovery. Omitting `--output-dir` leaves no durable authoring bundle.

For a caller-owned source digest, provide the complete 256-row `root_seed_census` recipe.
This route selects 64 roots: indices `0`–`31` in each context.
Each recipe row declares 17 stream commitments and a separate passive-probe commitment.
Use the [no-contact allocation and serialization recipe](../../docs/response-input-formats.md#supply-a-caller-owned-numeric-root-census).
The empty shipped census selects only its fixed bundled allocation.
Foreign model banks or prior inspections require separately reviewed current exports before authoring.

The seed label and target prefix are public development choices. Any edited input must satisfy its strict registered schema and exposure role. The shipped study does not permit changing the scientific clock, cohort, receiver or thresholds to obtain a passing result.

The [selected information-response check](../../tests/test_information_prediction_held_source.py)
uses its matching held plan, complete prior census and fitted information bank.
It binds a common pre-parent frame on one exposed development root in both views.
It measures the parent handoff before prediction with all seven bank arms. The S/H/SK/HK feature widths are 8/128/16/136. A matched
HOLD/+16 first-port future realizes 1.024 dimensionless impulse and yields
five native displacement/preservation readouts. The two-view terminal paired
receiver differs by less than 0.01. The bank and this one-root assay do not
provide a 64-root information result.

## Retained information-response diagnostics

Use the installed [information-response statistics](../../src/empirical_lawhood/adapters/methods/information_response/posthoc_statistics.py)
for the retained two-future, two-view, seven-arm chart. The
[array reduction](../../src/empirical_lawhood/adapters/methods/information_response/posthoc_reduction.py)
accepts the original retained arrays, separate development arrays, frozen bank
and explicit root IDs. It returns the report, derived arrays, root atlas and
casebook. The [pulse supplement](../../src/empirical_lawhood/adapters/methods/information_response/posthoc_pulse.py)
adds sign/duration, diagonal/off-diagonal and future-sensitivity reductions.

Authenticate each supplied array and bank against its original receipt census.
Obtain separate outcome-visible analysis authority before calling these library
functions. They preserve 32 independent roots per context, 16 separate development
roots, whole-root folds and bootstrap resampling. Handoff features and the
pre-parent comparison remain separate. Two futures do not identify a conditional
mean oracle. The reports remain post-hoc and nonpromotable.

These functions preserve the historical operator's calculations without its
private paths or authority wrapper. They perform no native work, publication or
issue. No CLI analysis executor or authentic input selection is supplied by this
library entry point.

The [information-response native extractor](../../src/empirical_lawhood/adapters/methods/information_response/posthoc_extraction.py)
reconstructs the original two-context, 64-root post-hoc feature arrays. It keeps
the pre-parent prefix frame distinct from the later handoff history, reproduces
every saved-bank forecast and validates the paired endpoint gains. Supply the
authenticated original bank, readout and native result/payload pairs after
separate analysis authorization. The extractor reuses the bounded native codec
and performs no acquisition, fitting or publication. Its arrays remain exposed
post-hoc evidence.

`concordant_win_power` in the [information-response comparison owner](../../src/empirical_lawhood/adapters/methods/information_response/comparison.py)
retains the original 32-root, 24-win probability grid. It assumes independent root events and the declared probability of a win concordant across both views.
It describes the first Holm threshold.
It supplies no joint-power calculation for the whole eight-test family. It performs no outcome contact or qualification.

## Obtain the workflow inputs

Obtain this bundle from the selected repository checkout or source distribution. The guide and study inputs are repository workflow files, not wheel resources. Run each command from the checkout root in an unactivated shell. The relative paths use that root.

Keep generated data and receipts in the declared external storage. A wheel can perform its advertised inspection and native-input checks with absolute paths. Source-bound authoring and issue require a clean checkout that executes its own tracked package.
