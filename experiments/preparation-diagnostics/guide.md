# Applicability sensitivity diagnostics

SPDX-License-Identifier: CC-BY-4.0

This workflow analyses the complete retained constructed Q8 and E32 results from [preparation applicability](../preparation-applicability/guide.md). It makes no simulator calls. Q8 remains development/qualification context; only the distinct32 E roots enter confirmatory probability accounting. The original numerical F and sealed protocol choices are preserved. Counterfactual bypass, fixed windows, oracle windows, threshold sweeps and numerical-view masks are separately labelled post-hoc diagnostics.

Use `uv run --no-sync empirical-lawhood workflow show preparation-diagnostics` for static discovery. Select the actual source checkout with `--project-root` and the guarded storage with `--operator-profile`, as described in [the CLI guide](../../docs/cli.md). Retain each complete run's recovery-index locator from `campaign status`, its exact selection JSON, run/issued-study IDs, and actual execution/reveal grant IDs. There is no supplied completed-results JSON: those identities must come from your current runs.

Run `uv run --no-sync empirical-lawhood campaign preparation-diagnostic-phase-prepare --help` for the exact Q or E phase preparation contract. Pass `--selection`, `--recovery-index`, `--run-id`, `--issued-study-id`, `--execution-authority-id`, `--reveal-authority-id` and a fresh `--output` under the guarded root. Preparation selects every required root and terminal receipt from the authenticated index, avoiding manual entry of hundreds of receipt IDs. Missing, incomplete, mismatched or unauthorised current inputs stop before protected payload reads.

Join the two prepared files with `uv run --no-sync empirical-lawhood campaign preparation-diagnostics-prepare --analysis-id my-diagnostics --qualification /absolute/Q.json --evaluation /absolute/E.json --bootstrap-seed-q 123456 --bootstrap-seed-e 654321 --output /absolute/new-diagnostics.json`. Choose distinct explicit bootstrap seeds that do not overlap either scientific allocation. The resulting editable analysis input binds the actual analysis source bytes. Inspect its schema with `uv run --no-sync empirical-lawhood config schema preparation-diagnostics`; use the standard config validation/preparation workflow for permitted edits. Immutable result evidence cannot be prepared as configuration.

Run `uv run --no-sync empirical-lawhood campaign preparation-diagnostics --input /absolute/new-diagnostics.json --relative-root analyses/my-diagnostics` with the selected global project/storage options. Use a fresh destination and optionally `--attempt-dir` for retained command progress/failure records. The analysis authenticates all40 root chains and recomputes their original reductions before publishing a separate outcome-visible report; it cannot reclassify the original experiment.

Reinspect using `uv run --no-sync empirical-lawhood campaign preparation-diagnostics-result --input /absolute/new-diagnostics.json --relative-root analyses/my-diagnostics`. The reader verifies current grants, exact terminal receipts, report bytes and lineage without rerunning numerical reductions. If publication is interrupted, inspect the retained attempt and exact publication files; choose a fresh output root rather than overwriting partial evidence.

Reports retain all Q8/E32 roots, separate first/last/both-view/envelope accounting, nonattempt/negative outcomes, selected consumer limits and separate support-only bypass results. Whole-root bootstrap comparisons include excluded roots as zero contributions in the original requested denominator. E32 false-admission and full-valid bounds use the actual complete root counts; missingness is UNEVALUABLE, never silently dropped. These reports do not create scientific qualification, issue authority or a release tag.
