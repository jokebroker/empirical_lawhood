# Prepared response: native canary and candidate authoring

SPDX-License-Identifier: CC-BY-4.0

This guide gives instructions for the six-matrix prepared-response canary and candidate authoring.
It separates exposed native development from qualified-parent refinement and calibration.
Use it to run the canary or construct the permitted development candidate.

**Exposed development and qualified-parent preflight.** The canary runs one public root. Authoring compiles a nonpromotable candidate. The authentic negative prepared-response parent supplies no common qualified charter.

This six-matrix numerical study asks whether a prepared system supports a common response charter and its dependent selection/policy contracts. Information and causal fitted-bank tasks have their own [information](../information-response/guide.md) and [causal](../causal-response/guide.md) guides. Finite response-law and [post-hoc causal-transfer](../causal-transfer-audit/guide.md) tasks retain separate parent requirements.

## Read results and failures

The canary report separates `independent_roots`, `nested_numerical_views`, `views` and `evidence_role`.
Native clocks are in `clock_unit`; response is in `force_unit`.
Held authoring reports provider construction and candidate compilation without native tasks.
A dependent-input refusal is a parent/authority stop, not an unsupported native result.

Read [the common result and failure guide](../../docs/results-and-failures.md) for retained attempts,
stdout/stderr and same-identity issued recovery. The route-specific outputs and stops below remain binding.
Use `workflow show prepared-response --format json` for static command effects and prerequisite roles.
Discovery does not inspect those prerequisites.

## Run the excluded native canary

The checked-in [canary input](prepared-canary.json)
runs one **excluded, public development root** through the retained six-matrix prepared source. From a clean target checkout:

```sh
uv sync --locked --python 3.11.14
uv run --no-sync empirical-lawhood campaign prepared-response-native-check \
  --config experiments/prepared-response/prepared-canary.json \
  --output-dir /absolute/development/prepared-response/attempt-001
```

The input is strict canonical JSON. The seed label and config identity are new
target development choices and are public. The source contract fixes a dimensionless underdamped Langevin clock and BAOAB steps of 0.001 and 0.0005.
It uses complex128 Hermitian state and a 256-tick linear preparation.
It fixes a causal 16-sample pre-parent port frame, five parent options and a 64-tick force pulse. This
canary chooses the assembling context, hold parent and +8 first-port word.
These are illustrative selections, not a nominated evaluation word.

Each
view reaches its pre-parent landmark at tick 1024, parent handoff at 1296 and
receiver at 1616. The requested word, accepted phase, applied force kicks,
realized impulse and paired terminal displacement receiver remain separate. Both views, the hold comparator and force arm are nested under **one**
stochastic root. The command reports no candidate, issue, source qualification
or lawhood result.

The [focused check](../../tests/test_prepared_response_development_input.py) loads the shipped input and runs both native views.
It tests the independent force impulse integral and pre/post pulse cutoff.
It rejects a promoted or malformed input.
The native phase consumes the retained six-matrix state, Hermitian gradient,
passive observer and causal port calculations. It is a checked six-matrix consumer of
those constitutive calculations. It is not a standalone matrix program.

## Author an exposed development candidate

The local [prepared-source-qualification-author.json](prepared-source-qualification-author.json) selects this route. Use absolute paths for the held source, reviewed plan, design packet and complete prior-exposure census. This unfitted prepared route forbids a model bank. Choose a new output directory outside the checkout.

```sh
uv sync --locked --python 3.11.14
uv run --no-sync empirical-lawhood --project-root "$PWD" campaign matrix-response-author \
  --config experiments/prepared-response/prepared-source-qualification-author.json \
  --source-root "$PREPARED_RESPONSE_HELD_SOURCE_ROOT" \
  --plan "$PREPARED_RESPONSE_PLAN" \
  --design-packet "$PREPARED_RESPONSE_DESIGN_PACKET" \
  --prior-exposure "$PREPARED_RESPONSE_PRIOR_EXPOSURE" \
  --output-dir "$PREPARED_RESPONSE_NEW_AUTHORING_DIRECTORY"
```

The candidate is `EXPOSED_DEVELOPMENT_NONPROMOTABLE`. The summary reports provider construction and candidate compilation separately. It executes no native task and grants no issue or reveal authority. See [external input formats and shared authoring contracts](../../docs/response-input-formats.md) for exact formats, byte limits, exclusions, expected emitted records and refusal codes.

For a caller-owned source digest, provide all 32 qualification rows in `root_seed_census`.
Each row declares 17 stream commitments and a separate passive-probe commitment.
Use the [no-contact allocation and serialization recipe](../../docs/response-input-formats.md#supply-a-caller-owned-numeric-root-census).
The empty shipped census selects only its fixed bundled allocation.
Current authoring accepts current-schema census inputs. Foreign history requires a separately reviewed current export.

The seed label and target prefix are public development choices. Any edited input must satisfy its strict registered schema and exposure role. The shipped study does not permit changing the scientific clock, cohort, receiver or thresholds to obtain a passing result.

The [selected prepared-response source check](../../tests/test_prepared_response_held_source.py)
also loads the shipped prepared-response JSON with explicit held plan, design and complete
prior exposure inputs. It builds the registered source provider with zero native contact.
It then runs one public development root through five parent continuations in both views. The unfitted prepared-response menu retains HOLD and
both signs of four directions at amplitudes 8 and 16, all 17 words. A matched HOLD/+8 pair per parent preserves the requested word and accepted phase.
Each reference view has 64 nonzero pulse intervals and 0.512 dimensionless realized impulse.
The paired displacement receiver is finite.

The two numerical views
agree on each receiver within 0.01, and the five parent receivers are not
identical. The causal port frame freezes from the sixteen pre-parent samples.
Poisoned later observations cannot enter that frame. This single exposed root
does not supply the 32-root prepared-response screen or reverse the authentic retained prepared failure.

## Check dependent selection and policy inputs

Dependent refinement and fresh response calibration have distinct selection and calibrated policy contracts.
The prepared-response authoring start does not select their providers or qualify their fresh rosters. The authentic retained prepared terminal evaluation has 96 context
screens. Applying the retained `PreparedResponseSourceQualificationContextScreen.passing` rule gives
zero passing screens and therefore no common prepared-response charter. It cannot nominate
the amplitude or justify a dependent refinement candidate.

Dependent refinement requires a qualified, typed prepared-response
evaluation with a selected common charter and measured excluded-canary
candidate costs. Fresh response calibration requires the resulting authentic dependent refinement nominal library with
`NOMINATED_FOR_FRESH_CALIBRATION`. Their retained builders refuse when those
inputs are absent. A genuine prospective prepared-response/information-response/causal-response start still needs an
authenticated complete prior-source inventory, unexposed units and streams,
and separate typed authority before issue.

The target [dependent refinement](prepared-dependent-refinement-input.json) and
[fresh response calibration](prepared-fresh-response-calibration-input.json) selectors use
`campaign dependent-response-input-check --config ... --source-root ...
--parent-manifest ... --custody ... --reveal-record ... --analysis-record ...`. With the retained prepared manifest but no target custody, both installed-CLI starts exit 3 at `DEPENDENT_REFINEMENT_TARGET_CUSTODY_REQUIRED` or `FRESH_RESPONSE_CALIBRATION_TARGET_CUSTODY_REQUIRED`.
No parent outcome read, provider or native task follows. The shared `ImportedResponseParentCustody` declaration identifies
source manifest, artifact/receipt digests and original root IDs but does not
grant authority. The [synthetic inventory replay](../../tests/test_response_parent_custody.py)
uses separately resolved target custody, reveal and analysis grants before
opening a source manifest.

It validates the terminal's complete successful
receipt roster, output materializations, publication markers, source parent
artifact, stage scientific-product identity and original physical roots against
bounded bytes. The installed `ResponseExternalParentAuthorityStore` replays three distinct
`ResponseParentTargetGrant` publications (custody, reveal, analysis) from
`authority/prepared-response-parent-grants/<grant_id>.json` under an explicitly selected
operator profile. Each needs its immutable manifest and exact parent/route/root
join. The input command never mints a grant.

Without the profile it refuses the
missing store. Self-declared files outside the trusted store are rejected.

If the parent is a qualified current prepared-response evaluation or dependent refinement library, supply `--authoring-input`.
Use canonical `PreparedResponseDependentAuthoring` JSON with exact plan/design/prior identities and bounded candidate costs. The checker authenticates custody before the parent read.
It binds retained dependent-refinement or fresh-calibration authoring and the registered source provider.
It reports 128/192 development roots with zero native tasks executed. The
[positive and negative fixtures](../../tests/test_response_dependent_binding.py)
validate those joins without supplying scientific evidence. A historical-schema
parent refuses `PREPARED_RESPONSE_DEPENDENT_TARGET_TYPED_PARENT_REQUIRED`. No namespace
conversion is performed. A negative prepared-response charter refuses
`DEPENDENT_REFINEMENT_NO_COMMON_QUALIFIED_CHARTER`, and fresh response calibration requires a nominated dependent refinement library.

## Obtain the workflow inputs

Obtain this bundle from the selected repository checkout or source distribution. The guide and study inputs are repository workflow files, not wheel resources. Run each command from the checkout root in an unactivated shell. The relative paths use that root.

Keep generated data and receipts in the declared external storage. A wheel can perform its advertised inspection and native-input checks with absolute paths. Source-bound authoring and issue require a clean checkout that executes its own tracked package.
